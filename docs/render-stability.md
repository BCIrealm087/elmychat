# Message paint stability

The operator reported intermittent overlapping messages and flicker during moderate/fast chat. Inspection found a reproducible paint hazard: native roots retain auto height, but a relative bottom clip inset can expand when an emote or other native content grows before the coordinator receives the resize. The root then paints outside its assigned slot. This mechanism is covered by synthetic regressions; it does not establish every cause of the reported live OBS flicker.

The shared adapter now bounds each root's clip with absolute pixel polygon coordinates in the root's local space. Content can still grow and be measured at its natural height, while only the previous confirmed slot paints until relayout. Existing content remains visible during that wait. New outermost supported hosts are hidden by an owned stylesheet before discovery, including descendants that explicitly set visibility. Inline opacity admits placed roots; nested supported renderers stay native content. Detected key changes and unkeyed content replacement clear/hide the old placement in the mutation observer before the next paint.

Native host transitions and animations are disabled during attachment, preventing native fades or position interpolation from competing with compositor placement. Descendant markup, emotes, typography and animations are untouched. Styles restore on stop/failure/pagehide, and the admission stylesheet is removed. Foreign guard removal/text changes trigger repair without an idle observer feedback loop. These decorations retain the existing root/report/style bounds and add only one stylesheet per adapter.

Each complete placement snapshot now applies synchronously in one browser task before acknowledgment, canceling a queued observer frame first. The coordinator sends changed snapshots to both sources together, with at most two concurrent layout commands. Report order, serial cycles, increasing revisions, session/width rejection, bounded command deadlines and source failure isolation remain intact. Separate source documents can still paint at different times: this reduces dispatch skew but does not promise atomic cross-frame rendering. Native removals, inactive-frame throttling, abrupt transport loss and live selector changes retain their existing support limits.

`test/browser/render-stability.test.js` covers both adapters with delayed native growth across several screenshot frames, transparent gaps, intact following-message pixels, natural height reports, immediate snapshot geometry, disabled host motion, shrink identity, new-host hiding before discovery, nested-renderer visibility, reuse hiding before animation-frame work, guard repair/idle behavior and exact restoration. CI artifacts include `twitch-delayed-growth.png` and `youtube-delayed-growth.png`. The coordinator regression holds one source acknowledgment while verifying the other request completes, and checks coalesced cycles and bounded pending commands. Existing cross-origin CDP, sustained-load, ASCII-art and platform-mark suites remain part of `npm run check:all`.

Local syntax and all 43 Node tests passed. Local browser execution was blocked by the absent pinned Chromium executable; browser verification must come from the Windows/Linux CI jobs. Synthetic success does not establish prolonged live OBS stability. No settings change or new operator workflow is required.
